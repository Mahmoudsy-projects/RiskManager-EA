# v95 — BUG-059 (لگ): کم‌کردن فراخوانی‌های هم‌گام با UI چارت
لاگ v94: ~۱۰۰۰ms قفل فقط داخل UpdateCandleTimerChart و UpdateSessionWindowsVertical (به‌صورت متناوب، در بازه‌های ~۱۵ثانیه‌ای)؛ حالت عادی ~۳۰ms (همه ChartRedraw).
تغییرات (فقط RM_Tools.mqh):
1. UpdateCandleTimerChart: اگه متن/قیمت/زمان/رنگ عوض نشده باشه هیچ ObjectSet/ChartRedraw انجام نمی‌شه؛ بازه‌ی قیمتی حداکثر ۱ بار در ثانیه و رنگ پس‌زمینه ۲ ثانیه یه‌بار خونده می‌شه.
2. UpdateSessionWindowsVertical و SessionLevel_UpdateVertical: از تیک حداکثر هر ۳ ثانیه (قبلاً هر تیک)؛ زوم/اسکرول همچنان از CHART_CHANGE فوراً rebuild می‌شه.
3. تشخیصی موقت: خط `[RM-PERF] SLOWSTEP <مرحله> <ms>` اگه یه مرحله >۱۵۰ms طول بکشه (حداکثر ۱ خط/ثانیه) - برای پیدا کردن دقیق فراخوانیِ قفل‌کننده. بعد از پیدا شدن علت حذف می‌شه.
کامپایل اجرا نشده (فقط تعادل پرانتز/آکولاد چک شد). قبل از کامپایل .ex4 قدیمی پاک شود.

## یافته‌ی لاگ دوم + اصلاح اصلی (Key Time / Session Windows)
تست محمود: با خطوط عمودی سشن روشن لگ بود (ChartRedraw تا ~۱۰۰۰ms)، با خاموش‌کردنشون لگ رفت. علت: ~۴۵۰ خط OBJ_VLINE خط‌چین + ~۴۵۰ لیبل (۳۲ روز × ۱۴ خط) همیشه ساخته می‌شد.
اصلاح: BuildSessionWindows فقط خطوطی رو می‌سازه که از (لبه‌ی چپ ناحیه‌ی دیده‌شده - ۱ روز) جدیدترن (g_swCullTime). اسکرول به عقب → CHART_CHANGE بازسازی می‌کنه؛ اگه رویداد به‌خاطر throttle گم شد، چک ۳ثانیه‌ای UpdateSessionWindowsVertical بازسازی می‌کنه.
Session Level (باکس‌های سشن) هنوز دست‌نخورده (۳۲ روز × ۳ باکس) - اگه لگ ادامه داشت همین الگو رو اونجا هم می‌زنیم.
